Project Overview

What I Built & Why

A real-world, client-facing platform that serves three distinct user roles, processes real payments, and runs in production at www.b-secret.com.

The Problem

A beauty salon with 4 employees, 177+ services across 8 categories, and customers booking via WhatsApp and phone calls. No centralized system for availability, payments, scheduling, or employee performance tracking. Zero online presence for SEO discoverability.

The Solution

A full-stack platform with a public-facing booking experience, real-time dashboards for three roles (customer, employee, admin), integrated Stripe payments with deposit support, a loyalty rewards program, and SEO-optimized category landing pages — all internationalized in English and Romanian.

Engineering Decisions

Architecture Trade-Offs & Rationale

Convex Over Prisma/Drizzle

Chose Convex for its built-in WebSocket reactivity — all dashboard data auto-updates without polling or manual cache invalidation. The trade-off is vendor lock-in, but the developer experience gains (type-safe queries, zero-config subscriptions) justified the choice for a real-time booking system.

Soft vs. Strict Role Checks

Implemented dual auth patterns: softRequireRole() returns null (for graceful UI degradation in queries) while requireRole() throws errors (for mutation protection). This prevents error screens for legitimate UI variations while maintaining strict security on data mutations.

Time-as-Minutes for Slot Computation

The availability engine converts all times to minutes-since-midnight for fast integer range comparisons instead of Date object manipulation. This simplifies conflict detection logic and eliminates timezone edge cases in the slot calculation algorithm.

Dual CSP Configuration Strategy

Vercel overrides Next.js security headers in production, requiring both next.config.ts (for development) and vercel.json (for production) to stay synchronized. This is documented in CLAUDE.md to prevent security regressions during AI-assisted development.

Locale as Route Segment

Using [locale] as a dynamic route segment with "prefix as-needed" strategy instead of redirects. Romanian (default) has no prefix, English gets /en/. This maintains clean canonical URLs while preserving SEO integrity with hreflang tags.

Prices in Cents

All monetary values stored as integers (cents/bani). 3500 = 35.00 RON. This avoids floating-point precision issues common in financial calculations, and aligns with Stripe's API which also expects amounts in the smallest currency unit.
